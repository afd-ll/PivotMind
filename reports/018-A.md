## 问题 1：系统缺乏时间连续性 ——"静态快照"架构瓶颈

**位置**: 架构层面 — `demos/digital_life.c:568` `fgets()` 阻塞主循环

```
fgets(…) → dialog_process(…) → printf(…) → fgets(…)  // 纯离散
```

当前系统是纯事件驱动的：等待用户输入 → 处理 → 输出 → 再次等待。在无人交互时系统完全静止——没有激活衰减、没有念头涌现、没有情绪漂移、没有记忆巩固。

**根因**：缺少独立后台时间基准。ActiveLearner 虽然是一个后台线程，但它是任务驱动（5分钟一次学习）而非时间驱动（每秒维护系统状态）。

**影响**：系统"活着"只在对用户响应时，其余时间处于冻结状态。这违背了"生命 = 持续接受刺激 + 持续自我调整"的核心理念。

## 问题 2：活跃节点无自然消退 —— 激活值缺乏"遗忘"维度

**位置**: `huarong_topology.h:45` — `float activation` 字段

```c
typedef struct ReasoningNode {
    float activation;  // 当前激活值 — 无自动衰减机制
    ...
};
```

当前 `activation` 仅在对话处理中被修改（激活传播 + 重置），对话间隙无变化。如果一次长对话激活了大量节点，这些节点会保持高激活直到下一轮 `master_reset_activations()` 被调用——可能间隔数分钟到数小时。

**根因**：激活值缺乏独立于对话流程的时间衰减。对话线程不活跃时，拓扑状态冻结。

**影响**：
- 旧激活残留污染新一轮推理的激活场
- 无"遗忘"权重衰减，高频概念永远占优
- 无法模拟大脑的背景神经活动消退

## 问题 3：CognitiveState 缺乏内稳态回归

**位置**: `cognitive_params.h:31` — `CognitiveState` 结构体

```c
typedef struct {
    float drive_curiosity, drive_hunger, drive_social, drive_comfort;
    float emotion_pleasure, emotion_pain, emotion_security;
    float valence;
    float explore_rate;
} CognitiveState;
```

当前 `CognitiveState` 仅在对话交互中被修改（通过 `cognitive_state_update()`），无交互时永不变化。如果用户在一次互动中留下负面反馈，系统的 `emotion_pain` 会持续高企直到下一次交互——可能间隔数小时。

**根因**：缺少向基线（内稳态）缓慢回归的机制。生物情绪有天然的时间衰减曲线。

**影响**：情绪状态无自主恢复能力，完全依赖外部交互来"修复"。

## 问题 4：设计与线程安全策略

### 4.1 线程模型

采用独立 `pthread` 后台线程，遵循 `ActiveLearner` 已有的模式：

```
主线程:  fgets() → dialog_process() → printf() → 循环
时钟线程: sleep(1s) → tick → 循环
```

### 4.2 锁策略

| 操作 | 锁类型 | 持有时间 | 风险 |
|------|--------|----------|------|
| 激活衰减遍历 | `pthread_rwlock_rdlock` (MasterTopology.rwlock) | < 5ms | 读锁不阻塞其他读，不阻塞前台 |
| 自发激活注入 | `pthread_rwlock_rdlock` (同上) | < 1ms | 无 |
| 认知状态漂移 | 无锁（x86 浮点写入天然原子，竞争窗口极小） | < 1ms | 低 |
| 记忆巩固 | memory_system 内部 mutex | < 50ms | 低 |

**设计理由**：
- 复用 `MasterTopology.rwlock` 而非新建锁——避免死锁风险
- 读锁之间不互斥——不影响对话线程的读锁需求
- 认知状态漂移不用锁——`CognitiveState` 的写竞争极低频（对话线程每轮最多改一次，时钟线程每 tick 改一次），x86 对齐浮点写入本身就是原子的

### 4.3 激活衰减方案

```
node->activation *= 0.97f  // 每秒衰减 3%
activation < 0.01f → 归零
```

持有读锁即可执行——只修改 `float activation`，不修改拓扑结构（节点增删、边增删）。

### 4.4 自发激活方案

```
每 tick 期望激活次数 = 全拓扑节点总数 × 0.0001
在随机拓扑的随机节点注入 0.1~0.2 的弱激活
```

按期望值随机选择而非全员 `rand()`（避免 90000 次/tick 开销）。

### 4.5 认知状态漂移方案

```
drives[i]  = drives[i]  × 0.995 + baseline[i] × 0.005  // ~200秒时间常数
emotions[i] = emotions[i] × 0.995 + baseline[i] × 0.005
valence    = valence × 0.998  // 向中性0回归
explore_rate = 0.5 + valence × 0.5  // 效价调制探索率
```

### 4.6 记忆巩固 tick 方案

每 10 个时钟 tick（~10 秒）调用一次 `memory_consolidate()`。`memory_consolidate()` 内部已有互斥锁保护，不需要在 BackgroundClock 侧额外加锁。

## 问题 5：生命周期集成设计

### DigitalLifeSystem 集成点

```
digital_life_create()   → background_clock_create()     [第 6 步，dialog 创建后]
digital_life_start()    → background_clock_start()      [learner 启动后]
digital_life_stop()     → background_clock_stop()       [learner 停止前]
digital_life_destroy()  → background_clock_destroy()    [dialog 销毁前]
```

**销毁顺序**：learner → bg_clock → dialog → topology → memory → causal_graph

bg_clock 引用 `dialog->cognitive_state`，必须在 dialog 销毁前停止。这个顺序保证了无 use-after-free。

## 风险评估

| 风险 | 级别 | 缓解 |
|------|------|------|
| 读锁持有时间过长阻塞对话写 | 低 | 遍历 < 5ms，远低于正常对话轮次间隔 |
| rand() 质量影响自发激活分布 | 低 | 自发激活本身就是低概率噪声，无需高质量随机源 |
| CognitiveState 竞争导致数据撕裂 | 极低 | 浮点写入在 x86 上的对齐写入天然原子 |
| memory_consolidate() 频率过高影响性能 | 低 | 10 秒间隔，且内部已有 mutex |
| 后台线程无法正常退出 | 低 | 采用 `volatile int is_running` + `pthread_join`，与 ActiveLearner 模式一致 |

---

## 总结

BackgroundClock 解决了系统最根本的架构缺陷——时间连续性缺失。通过独立的后台时钟线程，系统在无人交互时也能持续运转，实现了"数字生命"的基本条件：生命不是一个状态，而是一个持续过程。

设计遵循项目核心约束：赫布路线，只读锁遍历，不引入反向传播/attention/transformer，增量修改不重构。
