## 问题 1：贪心走边缺乏输入锚定，主题漂移不可控

**位置**: `multi_topology.c:1395`

```c
float score = base_score * valence_mod * (0.5f + 0.5f * intent_weight);
```

当前 `context_features` 从路径节点累积而来，但缺乏原始输入语义的持续约束。路径走到第 8-10 步时，均值特征已经和输入问题几乎无关。

**根因**：走边评分只看"当前节点出边 + 路径上下文"，没有"这条路径是否还在回答原始问题"的检验。

**影响**：回复后半段偏离主题，尤其在长回复中表现明显。

## 问题 2：意图调节过于粗糙

**位置**: `multi_topology.c:1395` + `dialog_system.c:126`

```c
// 走边：全局标量缩放
float score = base_score * valence_mod * (0.5f + 0.5f * intent_weight);

// 激活传播：逐拓扑乘性
new_activation *= task->intent_weights[sub->type];
```

`intent_weight` 是一个全局标量（对特定拓扑），它平等地缩放该拓扑内的所有边。但"为什么"意图应偏好因果边，"怎么做"应偏好时序边——这在当前架构中完全缺失。

**根因**：`connection_motivational_bias` 字段已存在但未被意图感知——它只是一个静态偏置，不随意图动态调整。

## 问题 3：回复生成是串行兜底链

**位置**: `dialog_generate.c:25-246`

```
精确记忆匹配 → 拓扑生成 → 贪心走边 → 最高激活兜底 → 记忆回退 → "我在思考..."
```

各路来源**串行**尝试，前面的失败了才试后面的。问题是：当拓扑生成了质量勉强及格的结果，但走边其实能生成更好的时，系统不会考虑走边的候选。

**根因**：`dialog_generate()` 设计为串行回退链，高优先级路径占据输出后低优先级路径永远没有机会。

## 问题 4：意图识别存在误匹配风险

**位置**: `dialog_intent.c:31-37`

```c
static int contains_keyword(const char* text, const char** keywords, int count) {
    for (int i = 0; i < count; i++) {
        if (strstr(text, keywords[i]) != NULL) return 1;
    }
    return 0;
}
```

`strstr("servers", "vs")` 会错误匹配 "vs" → 识别为"比较"意图。对非中文关键词缺少词边界检查。

**影响**：低概率但一旦发生会导致意图分类错误，进而影响整个推理管线。

---

## 问题 5：复合节点已有机制但走边未感知

`cognitive_controller_scan_patterns()` 已在概念拓扑中创建复合节点，但 `topology_walk_greedy()` 仅遍历词汇拓扑的边，不会主动跳转到概念拓扑中使用这些复合节点。

**根因**：走边和概念涌现是两条独立管线，没有在生成阶段打通。

---

## 审查结论

| 编号 | 问题 | 严重度 | 修复策略 |
|------|------|--------|---------|
| P1 | 输入锚定缺失 | 高 | 走边加入 query_anchor 向量 + 锚点偏离惩罚 |
| P2 | 意图调节粗糙 | 中 | 意图→边类型神经调质式选择性增强 |
| P3 | 串行兜底链 | 高 | 竞争队列：并行生成多源候选 + 统一激活场竞争 |
| P4 | 意图误匹配 | 低 | 非中文关键词加词边界检查 |
| P5 | 复合节点未打通 | 中 | 走边增加跨拓扑跳跃到概念拓扑的候选 |

**建议实施顺序**：P1 → P3 → P2 → P5 → P4
