# 玄枢路径编码 + 递归抽象 实现计划

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** 用路径编码替代纯共现建边，通过递归抽象让语义从路径中自然生长出来。

**架构:** 在现有9个子拓扑之上，新增第10个模板拓扑（TOPO_TEMPLATE）。路径遍历时增量记录三元组频率，统计显著的高频路径自动抽象为模板节点，模板通过跨拓扑投票影响路径生成。

**约束:** Pi 3B编译验证，Dell G15训练。不改现有9个拓扑的底层结构。不引入transformer/外部模型。

## 关键设计决策（与计划的偏差）

### 1. PathFrequencyTable 挂在 MasterTopology 上
- **计划:** 独立创建，不走 MasterTopology
- **实际:** `master->freq_table` 随 MasterTopology 生命周期管理
- **原因:** 频率表需要在所有走边调用路径中持续积累，挂 master 上最自然

### 2. 走边时实时记录三元组
- **计划:** 仅在分析工具中后处理路径
- **实际:** `topology_walk_greedy` 每走一步自动调用 `path_freq_table_record`
- **代码位置:** `multi_topology.c:1514` — 每次选定 next 节点后
- **效果:** 频率表在对话、学习、训练所有调用路径中持续积累

### 3. 模板重建用实时频率表
- **计划:** 每次重新走边采集
- **实际:** `auto_build_templates` 直接用 `master->freq_table` 中积累的数据
- **效果:** 模板随使用频率自然生长，不需要专门的采集阶段

### 4. TOPO_TEMPLATE 枚举定义在 multi_topology.h
- **计划:** 在 trace_wisdom_topology.h 中定义
- **实际:** 在 multi_topology.h 中定义，效果等效

## P0: 三元组频率统计 ✅

### Task 1: PathFrequencyTable 数据结构 ✅

**文件:** `include/path_encoding.h`, `src/path_encoding.c`

**实现:**
- LRU哈希表，65536桶
- PathTripletRecord: node_a, node_b, node_c, topo_id, count, last_seen, is_active
- 哈希: `(node_a * 31 + node_b * 17 + node_c * 7 + topo_id) & BUCKET_MASK`
- 线性探测冲突处理
- pthread_mutex 线程安全

### Task 2: 在 topology_walk_greedy 中实时记录三元组 ✅

**文件:** `src/multi_topology.c:1514`, `include/multi_topology.h`

**实现:**
```c
// multi_topology.c:1514 — 每次选定 next 节点后
path_freq_table_record(master->freq_table, sub->topo_id,
                       trip_a, trip_b, trip_c);
```
- MasterTopology 添加 `PathFrequencyTable* freq_table`
- 频率表随 master 生命周期创建/销毁

### Task 3: 不可分解性评分 ✅

**文件:** `src/path_encoding.c`

**公式:**
```c
float ir_ratio = real_freq / (expected_freq + 1e-10f);
// real_freq = triplet->count / total_triplets
// expected_freq = P(A→B) × P(B→C)
// P(A→B) = edge_weight(A→B) / sum_of_outgoing_weights(A)
```
