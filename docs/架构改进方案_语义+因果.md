## 一、当前问题

训练20轮（292K QA）后，走边贪心输出从乱码→"我再靠自到看👋大老是"。
管线通了，但输出散——因为赫布边只看共现，不看语境。

**根因：** `topology_walk_greedy()` 每次只看当前节点的出边权重选下一步，
不看已走路径的联合激活模式，也不参考其他拓扑的语义关系。

## 二、改动方案（两步）

### 第一步：接语义模块做投票源（优先）

**目标：** 路径回溯投票时，同时查语义拓扑的连接边作为投票信号。

**改动文件：** `src/multi_topology.c`

**改动位置：** `topology_walk_greedy()` 函数，路径回溯投票循环（约 L1305-1325）

**现状代码（L1305-1325）：**
```c
// --- 路径回溯（第8维）: 已走路径的联合投票 ---
// 候选节点与已走路径中其他节点的连接强度
float path_context_score = 0.0f;
int path_ctx_count = 0;
for (int pi = 0; pi < path_len; pi++) {
    int pid = path_out[pi];
    if (pid < 0 || pid >= node_count || pid == current_id) continue;
    ReasoningNode* pn = net->nodes[pid];
    if (!pn) continue;
    for (int ej = 0; ej < pn->connection_count; ej++) {
        if (pn->connections[ej] == target) {
            path_context_score += pn->connection_weights[ej];
            break;
        }
    }
    path_ctx_count++;
}
float avg_path_weight = (path_ctx_count > 0) ? path_context_score / path_ctx_count : 0.0f;
float path_ctx_norm = avg_path_weight / 5.0f;
```

在现有词汇拓扑投票基础上，增加语义拓扑的跨拓扑投票。

## 三、凌文清的三个补充点

1. **边权归一化**：词汇拓扑赫布权重（共现频率归一化）和语义拓扑边权（概念关系强度）尺度不同。投票时需分拓扑归一化再加权求和。建议先硬编码系数（词汇0.6+语义0.4），后面调。

2. **因果图数据量**：如果因果图是空的或只有几条链，终止条件永远触发不了。**必须先验证数据量再决定优先级。**

3. **执行顺序**：先语义后因果。语义改善"每步选哪条边"（每步都用），因果改善"走到哪停"（需前面走对才有意义）。

---

## 四、凌文清的分歧点

凌介郉说因果模块只做终止条件，凌文清认为不够——

**因果模块还应约束走边方向：**
走边之前先用因果模块找一条从输入到某个回答概念的路径，
这条路径上的节点应获得额外的投票加权。
这样走边不是漫无目的地走，而是沿着因果链走。

这个比单纯的终止条件更根本。如果做方向约束，
改动量会更大（需要在走边前先做一次A*搜索定骨架）。
