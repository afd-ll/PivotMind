# tools/wiring_whitelist.txt —— `make check-wiring` 白名单
#
# 格式：一行一个函数名；`#` 起为注释（可单独成行，也可写在函数名后面说明理由）。
#   例：some_intentional_public_api   # 对外公共 API，按设计仓内无调用点
# 命中白名单的函数会被列为「① 豁免」，不计入门禁退出码。
#
# 何时该加（确认「零调用」是有意为之）：
#   · 对外的公共 API / 预留且已评审通过的扩展点；
#   · 只被函数指针、回调、动态加载或外部消费者间接引用（静态扫描看不见这些调用点）。
# 何时不该加（真死代码）：
#   · 「机制写了一半、调用点从未补」——应当去接线或删除，而不是登记豁免。
#
# ⚠️ 首次跑本门禁会命中若干真死函数；它们**刻意未登记豁免** ——
#    「先清死代码还是先加白名单」由项目负责人决定，不在此文件预设结论。
#
# （本文件暂不含生效条目；下面这行是格式示例，已注释、不起作用。）
