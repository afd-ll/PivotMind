# tools/wiring_whitelist.txt —— `make check-wiring` 白名单
#
# ⚠️ 2026-09-13 起键格式为 `<类> <名字>`（与 wiring_baseline.txt 一致）：
#      A <函数名>              零引用（有定义、全仓零引用）
#      D <函数名>              悬空声明（只有声明、全仓无定义）
#      B <函数名> <形参名>      显式丢弃 `(void)形参;`
#    `#` 起为注释（可单独成行，也可写在键后面说明理由）。
#    例：A some_intentional_public_api   # 对外公共 API，按设计仓内无调用点
# 命中白名单 ⇒ ① 豁免，不计入门禁退出码。
#
# 本文件 vs wiring_baseline.txt（**别混用**）：
#   whitelist = 「**结论：这样是对的**」——有意为之；
#   baseline  = 「**知道，还没处置**」——真欠账，等排期。
#
# 何时该加白名单（确认「零引用」是有意为之）：
#   · 对外的公共 API / 预留且已评审通过的扩展点；
#   · 只被函数指针、回调、动态加载或外部消费者间接引用
#     （注意：2026-09-13 起「取地址 / 无括号引用」已能被静态扫到，这条适用范围变窄）。
# 何时不该加（真死代码）：
#   · 「机制写了一半、调用点从未补」——应当去接线或删除，而不是登记豁免；
#     若一时处置不了，登记 tools/wiring_baseline.txt（那是欠账，不是豁免）。
#
# 历史：v0.5.36 建成时命中 8 个真死函数（**刻意未登记豁免**：先清死代码还是先加
