# 玄枢 PivotMind

**多拓扑联想网络认知引擎** —— 基于赫布学习的数字生命框架，纯 C 实现，零 AI 框架依赖。

> 生命不是一个状态，而是一个持续过程。

核心思想：节点同时激活就焊上去。反馈是纠偏器，不是学习源。系统在无人交互时也持续运转——激活衰减、念头涌现、情绪漂移、记忆巩固。

## 核心特性

### 1. 逐字拓扑网络
每个 UTF-8 中文字符作为独立节点（`ReasoningNode`），通过有向边承载语义关联。无需预分词——新组合自动适应，"学习"=「学」+「习」同时激活。

### 2. 9 层子拓扑分工
词汇 → 语义 → 情绪 → 语法 → 上下文 → 领域 → 语用 → 文化 → 概念，各司其职。跨拓扑连接（基于特征余弦相似度 + 动态命中跟踪）实现多层协同推理。

### 3. 竞争队列 + 走边推理
- **首选**：竞争队列（全图激活场 + 全局工作空间竞争读出，基于 Baars 理论）
- **回退**：贪心走边（五维评分函数，含输入锚点防主题漂移 + 神经调质式意图调制）

### 4. 认知调度中心
意图向量 × 上下文关联度 × 新颖性 × 在线学习因子。支持三级 retry 循环——不满意就缩域重搜。

### 5. 数字生命"心跳" —— BackgroundClock
独立后台线程每秒 tick，系统在无人交互时持续运转：
- **激活衰减**：活跃节点自然消退（每秒衰减 3%）
- **自发激活**：低概率随机注入弱激活，模拟"念头涌现"
- **状态漂移**：drive/emotion/valence 向基线 EMA 回归（时间常数 ~200s）
- **记忆巩固**：每 10 秒 STM→LTM 迁移

### 6. 在线赫布学习
对话中同时激活的节点对自动增强连接。ActiveLearner 后台线程周期性发现新关系、评估节点重要性、清理过时知识。

### 7. 状态持久化
二进制格式（v5），毫秒级加载，原子写入（先 .bak 备份再 rename 覆盖）。支持 23757+ 节点、18529+ 跨拓扑边的秒级恢复。

## 与传统 NLP/LLM 的本质区别

| 维度 | 传统 NLP/LLM | PivotMind 玄枢 |
|------|-------------|---------------|
| 知识表示 | 浮点向量（embedding） | 结构化节点 + 有向边 + 效价/置信度 |
| 学习方式 | 梯度反向传播（离线批量） | 赫布同时激活（在线实时） |
| 推理方式 | 神经网络前向传播 | 竞争队列 + 拓扑走边 |
| 时间连续性 | 无状态 token 预测 | 后台时钟驱动，激活/情绪持续演化 |
| 架构范式 | 中心化向量空间 | 多拓扑分域 + 跨拓扑连接 |
| 依赖 | PyTorch/TensorFlow + CUDA | 仅 pthread |
| 可解释性 | 黑盒 | 节点-边显式路径，全程可追溯 |

## 快速开始

```bash
# 编译（需 GCC + pthread）
make all

# 交互对话（需先有状态文件）
./build/bin/digital_life

# 查看统计
stats
```

### 构建目标

| 命令 | 说明 |
|------|------|
| `make all` | 构建所有目标（digital-life + seed-builder + debug-seed） |
| `make digital-life` | 构建交互对话程序（核心） |
| `make seed-builder` | 构建种子拓扑构建工具 |
| `make batch-learn` | 构建批量训练工具 |
| `make batch-learn-lowmem` | 低内存版（禁跨拓扑重建） |
| `make clean` | 清理 |

## 已知局限

1. **中文优先**：逐字拆分，英文/混合输入处理有限
2. **回复质量**：拓扑联想路线的输出连贯性不如 LLM
3. **无 GPU 加速**：纯 CPU 计算
4. **状态文件不跨架构**：x86_64 和 ARM 之间二进制不兼容
