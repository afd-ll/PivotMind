# 玄枢 PivotMind

**溯智网络 · 多拓扑认知引擎** —— 脑启发式语义联想系统，纯 C 实现，零 AI 框架依赖。

> 智能不是矩阵乘法的堆叠，而是激活在溯智网络中蔓延的涟漪。

---

## 是什么

玄枢是一套基于**溯智网络（HuarongTopologyNet）+ 赫布学习 + 多层扩散推理**的认知引擎。

**溯智网络**是玄枢的底层拓扑单元：每个概念是一个节点，共现即建边，连接携带权重、置信度与动机倾向三维属性。9 个子拓扑（词汇/语义/情绪/语法/上下文/领域/语用/文化/概念）各为一张独立的溯智网络，通过跨拓扑连接形成**9+1 多拓扑架构**（+1 为整合层）。激活沿四层同时扩散，竞争胜出者构成输出。

没有 Transformer，没有 embedding 向量，没有反向传播。只有节点、边、激活、衰减——以及一个永不停歇的后台时钟。

**当前版本：v0.2.3**

## 为什么这样做

| 传统 LLM | 玄枢 |
|----------|------|
| Token 预测，无状态 | 节点激活，有连续内部状态 |
| 梯度离线批量训练 | 赫布在线实时学习 |
| 单一 Embedding 空间 | **9+1 溯智网络多拓扑架构** |
| 神经网络黑盒 | 节点-边显式路径，可追溯 |
| 需要 GPU + 大量显存 | 仅 pthread，跑在 ARM 嵌入式板 |
| 推理与学习分离 | 对话即学习，学习即对话 |
| 无生理感知 | 内感受自检，三级健康响应 |

## 关键模块

### 溯智网络（底层拓扑单元）

溯智网络（`HuarongTopologyNet`）是玄枢全部认知能力的基础载体。名取"溯源而智生"之意——沿连接逆溯激活路径，浮现推理结果。

每张溯智网络由以下要素构成：

| 要素 | 说明 |
|------|------|
| **节点**（ReasoningNode） | 代表一个概念，携带特征向量、激活值、置信度 |
| **有向边** | 两节点间的共现/语义关联，携带权重 × 置信度 × 动机倾向三维属性 |
| **概念哈希表** | O(1) 按名称查找节点，万节点规模查找耗时 ~2μs |
| **赫布学习** | 共同激活的节点之间边权自动增强 |
| **突触缩放** | 长期弱激活的边自然衰减至遗忘 |

玄枢实例化 **9 张独立的溯智网络**（词汇/语义/情绪/语法/上下文/领域/语用/文化/概念），再加 1 个整合层，共同构成 **9+1 多拓扑架构**。每张网络独立学习、独立激活，跨网络连接基于特征余弦相似度自动建立。

---

### 多层扩散引擎（核心）

输入句子经滑动窗口分词（trigram → bigram → unigram 降级匹配），在四层网络同步扩散：

- **词汇层**：直接字面匹配，快速召回
- **语义层**：9 子拓扑跨层联想，触达相关概念
- **模板层**：识别"N的N是N""N对N有V"等句式模式，指导连接词插入
- **情绪层**：valence × arousal 加权，影响候选优先级

侧抑制机制（Lateral Inhibition）抑制共现过高的同质节点，保证输出多样性。

### 内感受自检（HealthMonitor）

引擎的"身体觉察"系统，持续监测三项生理指标：

| 指标 | 黄色预警门槛 | 红色紧急门槛 |
|------|------------|------------|
| RSS 增速 | > 2MB/min | > 10MB/min |
| 连接膨胀 | 新增 > 50k/min | 新增 > 200k/min |
| 推理冻结 | 响应 > 2s 占比 > 30% | > 80% |

- **GREEN**：正常运行
- **YELLOW**：日志告警 + 自动提高学习门槛
- **RED**：紧急状态存档 + 批量砍除弱边（权重×置信度 < 0.01 的边衰减至 50%）

### 概念哈希（O(1) 查找）

`HuarongTopologyNet` 内置哈希表，将 `O(n)` 的线性扫描优化为 `O(1)` 查找，大幅提升扩散速度。万节点规模下查找耗时从 ~200μs 降至 ~2μs。

### 突触缩放（Synaptic Scaling）

每 600 tick 扫描全图所有边：

```
权重 × 置信度 < 0.05  →  权重 × 0.9  （衰减）
权重 × 置信度 < 0.01  →  权重 × 0.5  （加速衰减）
权重 × 置信度 < 0.001 →  释放内存    （清除）
```

生物合理性设计：弱连接自然消退，强连接保留——不是粗暴删除，而是遗忘。

## 快速开始

### 编译

```bash
# 需要 GCC + pthread（无其他依赖）
make all

# ARM 交叉编译
make CC=aarch64-linux-gnu-gcc all
```

### 启动网关（推荐）

```bash
# 直接运行
./build/bin/pivotmind_gateway

# 作为系统服务（Armbian/Debian）
sudo systemctl enable --now pivotmind_gateway
```

网关默认监听 `:8080`，启动后 3-5 分钟完成状态加载（loading → ok）。

### API 示例

```bash
# 提问
curl -X POST http://localhost:8080/ask \
  -H "Content-Type: application/json" \
  -d '{"query": "什么是意识？"}'

# 喂料学习
curl -X POST http://localhost:8080/learn \
  -H "Content-Type: application/json" \
  -d '{"text": "意识是大脑神经网络产生的主观体验。"}'

# 查看状态
curl http://localhost:8080/status
```

### 批量喂料

```bash
# 用 Python 脚本批量训练
python3 tools/bulk_feeder.py --input data/corpus/ --rate 50

# 或用 shell 脚本
bash tools/teach.sh
```

### 构建目标

| 命令 | 说明 |
|------|------|
| `make all` | 构建全部目标 |
| `make gateway` | 仅构建 HTTP 网关 |
| `make digital-life` | 构建命令行交互版 |
| `make seed-builder` | 构建种子拓扑工具 |
| `make batch-learn` | 批量训练工具 |
| `make clean` | 清理构建产物 |

## 已知局限

- **中文优先**：逐字拆分天然契合中文，英文/混合输入体验有限
- **回复流畅度**：联想路径输出的句子不如 LLM 自然，仍在迭代
- **无 GPU 加速**：纯 CPU + pthread，不依赖 CUDA
- **状态文件二进制**：不跨架构（x86_64 和 ARM 不互通）
