## 二、改动（2 处，共 +45 / −2）

### 2.1 `src/dialog_generate.c` — 存量污染「出口闸」（`d644679` +24；判据收窄 `7bc4e3b` +11 −1）

新增 `bg20_is_polluted()`，在 `concept_is_outputtable()` 里作为第二道否决：

| # | 判据 | 依据 |
|---|---|---|
| ① | 含 `_` **且含非 ASCII** | 中文词里出现下划线必为污染；纯 ASCII 的 `a_b` 放行（契约） |
| ② | 含 U+2192 `→` 或骨架词「置信度」 | 与 BG-19 同源 |
| ③ | 含 `U+FE10–FE6F` | 与 BG-14 同源 |

- **不删数据、不改结构、不动状态格式** ⇒ 影响半径 = 本函数。
- ⚠️ **有意不套 BG-10 的 ASCII 判据** —— 那会误伤 `AI`/`OK`/`ID`/`IN`/`ON`；**出口侧必须比入口侧保守**。

### 2.2 `src/chinese.c` — `is_punctuation()` 3 字节分支补码位（`d644679` +10 −1）

原只覆盖 `U+3000–303F` / `U+FF00–FFEF`，漏三段同族标点 ⇒ 线上出现污染词 `馴﹔`。
现补 **`U+FE10–FE6F` 连续一段**（竖排 FE10–FE19 / 兼容形式 FE30–FE4F / 小写变体 FE50–FE6F），
三段全是标点形式、不含可组词字符 ⇒ **零误伤**。

⇒ 与 2.1 **两端一起收口**：此处防「进 vocab」，出口闸防「进回复」。
