## 三、步 3：`emergent_pos` 按语种实例化

### 3.1 病灶

```c
/* src/cognitive_controller.c —— 构造时就写死中文 */
cc->emergent_pos = emergent_pos_create("zh");
/* demos/gateway_system.c —— 启动初始化也写死中文 */
int pos_init = cc_init_emergent_pos(gw->prefrontal->controller, "zh");
```

`EmergentPOS` 的**语种唯一决定种子表**（`POS_CN_SEEDS` / `POS_EN_SEEDS`），
而实例是**单指针**、被 5 个持有者引用（`CognitiveController` / `ArticleReader` /
`TrainMode` / `DiffusionContext` / 各处直取）⇒ **结构上装不下第二种语言**。

### 3.2 改法（最小正确面：4 文件 + 1 demo，78+ / 14−）

| # | 文件 | 变更 |
|---|---|---|
| 1 | `include/emergent_pos.h` | `EmergentPOS` 新增 `PmLang lang`（实例的语种）；include `lang.h` |
| 2 | `src/emergent_pos.c` | `create` 记录语种；`save`/`load` 在 `filepath==NULL` 时**只允许中文实例** |
| 3 | `include/cognitive_controller.h` | 新增 `EmergentPOS* emergent_pos_slots[PM_LANG_COUNT]` + `cc_emergent_pos_for(cc, lang)` |
| 4 | `src/cognitive_controller.c` | `create` 走访问器；`destroy` 改**按槽遍历**；`cc_init_emergent_pos` 内部走访问器（**对外 API 兼容**） |
| 5 | `demos/gateway_system.c` | 写死的 `"zh"` → `NULL`（引擎默认语种） |

**两个关键设计取舍（都是"把结构做对"而不是"把功能做多"）：**

1. **保留 `cc->emergent_pos` 作为「主导语种那一槽的别名」** ⇒ 全仓 **100 处**既有取用点
   **零改动**。这是"加一个维度而不惊动下游"的做法 —— 与 `TopologyType` 不做 12→24 枚举爆炸
   （设计稿 §③）同一个思路：**语种是属性 + 取用入口，不是把类型数乘二**。
2. **非中文实例的默认落点 = 响亮拒绝**（不是静默覆盖）。若让所有语种共用
   `<home>/data/emergent_pos.bin`，第二个实例一存盘就会把中文锚点**静默抹掉**。
   本版的选择是：`save`/`load` 在 `filepath==NULL` 且语种非中文时**打印理由并返回 -1**。
   ⇒ 非中文实例**当前没有默认落点**（路径 SSOT 的 12 个位已满，本版**不动它**）——
   这是**明确登记的边界**，不是遗漏（见 §六）。

### 4.2 行为 A/B（180 例 × 3+3 轮，同一份线上状态只读快照）

**判据**：步 3 是**结构改造**（按语种实例化），中文路径行为**应当零变化** ⇒ 预期"无差异"。
（`before` = v0.5.41 的 gateway，`after` = 本版；同一快照、同一 `rand_pin.so`。）

| 组内（同一二进制多次跑） | 差异行 |
|---|---|
| before: `b1` vs `b2` | **0** |
| before: `b1` vs `b3` / `b2` vs `b3` | 10 / 10 |
| after: `a1` vs `a2` | **0** |
| after: `a1` vs `a3` / `a2` vs `a3` | 99 / 99 |

| 组间（before × after） | 差异行 |
|---|---|
| `b1` vs `a1` ／ `b1` vs `a2` ／ `b2` vs `a1` ／ `b2` vs `a2` | **0 ／ 0 ／ 0 ／ 0** |
| `b3` vs `a1` ／ `b3` vs `a2` | 10 / 10 |
| 任意轮 vs `a3` | 99 |

**结论**：
- ✅ **四轮干净样本（`b1`/`b2` × `a1`/`a2`）两两逐字节一致 ⇒ 步 3 的「行为中性」得到证实。**
  这是本次**最干净的一次 A/B** —— 因为预期本来就是"无差异"，实测吻合。
- ⚠️ `b3` 与 `a3` 是**组内抖动轮**（同一个二进制自己也会差 10 / 99 行）⇒ 再次印证
  **运行期非确定性**确实存在（A22/B1 复活感知区的副作用，见 084 §3.2 与本文 §六）。
- 🔑 **方法论留痕**：A/B 必须**先看组内、再看组间** —— 否则会把 `a3` 的 99 行
  误读成"步 3 的效果"（实际上它与本版改动无关）。

## 五、为什么这是第六版架构

`changelogs/README.md` 的规则：`0.Y.0` = **大型架构变化**。本版够格的地方不在于"改了多少行"，
而在于**语种从「一个字段」升成「一等结构」**：

| 层次 | v0.5.x 之前 | v0.6.0 |
|---|---|---|
| 判定 | 9 处各写各的（`& 0x80` / `strlen==3` / 裸码点） | **一处 SSOT**（`lang.h`） |
| 节点 | 无 `lang`，运行期从 `concept[0]` 现算 | **节点属性 + 落盘**（fmt 10），仍是 SSOT 的物化缓存 |
| 输出过滤 | 5 组字节粗判 + 1 处兜底 | **1 处统一过滤**，判据走 SSOT |
| 子系统 | `emergent_pos` 单实例 + 硬编码 `"zh"` | **按语种实例化**（槽位 + 取用入口） |
| 拓扑 | —— | 刻意**不动** `TopologyType`（语种是属性，不是拓扑维） |

## 六、诚实边界（不许当成功报告读）

1. **非中文实例没有默认落点** —— 路径 SSOT 的 12 个位已满，本版不改它；
   `save`/`load` 用默认路径会**拒绝**（响亮失败）。⇒ 英文实例**建了也存不下来**，
   等"真要跑英文"时再补路径位 + 迁移说明。
2. **英文路径未被任何真实数据走过** —— 本版把**结构**做对，但 `POS_EN_SEEDS` 这条路上
   没有语料喂养，**未做端到端验证**（也没有可验证的对象）。这是**结构先行**，不是功能交付。
3. **步 2 的 A/B 复现性不足**（见 084 §3.2 与 §七下面）：同二进制两次跑差 0~15 行
   ⇒ 端到端 A/B 的信噪比有限。
4. **未上线部署** —— 线上仍是 v0.5.34。
