## 一、来源与病灶

### 1.1 一个维度，两套口径

`src/diffusion.c` 里同一个「语种」维度跑着两套判据：

| 用途 | 判据 | 语义 |
|---|---|---|
| 扩散系数 `_lang_mult()` | `NODE_IS_CJK` = `pm_lang_of(x) == PM_LANG_ZH` | **真语种**（码点级）✅ |
| 输出过滤 5 组 | `pm_is_nonascii(x)` | **字节级粗判**（首字节 `& 0x80`）❌ |

`pm_is_nonascii()` 把**法文 `é`、日文假名、韩文谚文、CJK 标点、emoji 全当成「中文」**
（v0.6 设计方案 §1.2 真缺陷 2）。5 组站点（原 `:1808 / :1832 / :1872 / :1919 / :1948`）
各自手写一对：

```c
if (lang_dom > 0 && !pm_is_nonascii(X)) continue;
if (lang_dom < 0 &&  pm_is_nonascii(X)) continue;
```

### 1.2 静默后果

`lang_dom > 0`（中文主导）时，旧实现等于「**丢弃一切 ASCII**」——
输出里的**数字与 ASCII 标点被一起丢掉**（`lang_dom < 0` 时对称）。

> 这正是 B5 摸底的核心发现：**步 2 的实质不是「5 处合一」，而是「把口径升到真语种」**
> ⇒ 必然伴随行为变化 ⇒ 必须 A/B。

## 二、改法

新增 `static int _lang_keep(const char* w, int lang_dom)`（`src/diffusion.c`，放在 `_lang_mult` 上方），
5 组站点各两行 → 一行调用，统一走语种 SSOT（`include/lang.h`）。

**口径（老大 2026-09-14 定 —— 白名单只丢英文）**：

```c
static int _lang_keep(const char* w, int lang_dom) {
    if (lang_dom == 0 || !w || !w[0]) return 1;
    PmLang l = pm_lang_of(w);
    if (lang_dom > 0) return (l != PM_LANG_EN);              /* 只丢英文 */
    return (l == PM_LANG_EN || l == PM_LANG_UNKNOWN);        /* 英文主导：留 EN + 标点/数字 */
}
```

**三选一的口径为什么选它**：

| 口径 | 条件 | 后果 |
|---|---|---|
| (a) 只留中文 | `l == ZH` | 语义最纯，但 **CJK 标点 `。，！` 落 UNKNOWN ⇒ 会被误伤** |
| **(b) 只丢英文（选用）** | `l != EN` | 对纯中文语料**扰动最小**；标点/数字保住；`é`/`ü` 这类被判 EN 的被正确丢弃 |
| (c) 折中 | `ZH 或 UNKNOWN` | 标点保住，但假名/emoji 也放行 |

⇒ 选 (b)：**它同时修掉「é 被当中文」与「标点被当英文丢掉」两个错**，且行为变化可预期。

⚠️ **这是有意的口径升级，不是等价重构**。差异面：旧实现中文主导时丢 ASCII 标点/数字，
新实现保留它们（UNKNOWN ≠ EN）。

**未动**：`_lang_mult()`、`lang_dom` 的计算点（`:1322`）、
`demos/gateway_handlers.c:107` 的输出层兜底（理由见 §四）。

   混着同类噪声 —— 差异最大的 8 条全是在「**推理分解模式**」（PFE 路径，长回复）与
   「**礼貌兜底**」（34 字固定句）之间跳变，**那是 PFE 路径、与本次改动无关**。
2. **本次【未能】给出「改完更好 / 更坏」的可信结论**。能给的是两条：
   ① 判据按设计生效（标点保留是**直接观测**）；
   ② 端到端影响面大、**方向混合**（8 条"退化"、8 条"升级"，其余为词串变化）。
3. 判据在输出组装里是**承重**的 —— 122/165 的大面积变化是**必然**，不是异常
   （与 v0.5.38 那 3 处承重点同款结论）。
4. 🔴 **复现性退化的根因（推断，待单独追）**：v0.5.38 那次 A/B 是 `REPRO_OK`（0 行），
   本次退化到 0~15 行。最可能的原因是 **A22 / B1 让感知区「复活」** ——
   `perception_tick` 从「恒返 0」变成**真的会入队、真的会搜索**，后台 worker 活动
   给输出引入了非确定性。**这条本身值得单独立项。**
