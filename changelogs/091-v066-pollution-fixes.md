## 二、两处真实行为变化

### ① BG-13 A —— `is_punctuation` 的 ASCII 分支补全（`8edc4d2`，`src/chinese.c` +8/−5）

原 ASCII 分支是一串硬编码白名单（空白 + `, . ? ! ; : ' " ( ) [ ] { } < >`），
**漏了 `_`** 以及 `- + = / | ~ % $ # @ ^ & *` 一整批 ⇒ `is_punctuation("_")` 返回 0。

后果（线上实证）：`article_reader` 抽字不跳 `_`（`:452`）、建词不拦 `_`（`:529`），
而下划线过滤 `has_underscore` **只在 ASCII 分支里跑**（含中文的词全绕过）
⇒ 回复里的 `_X_` 骨架被当词建进 vocab（线上样本 `_尊師_` / `_謝_置信度%`）。

改法：改用 `<ctype.h>` 的 `ispunct()` 覆盖**全部** ASCII 标点；空白仍单独判（ispunct 不含空白）。
影响半径：`is_punctuation` 全仓仅 **3 个调用点**（`article_reader.c:452` / `:529`、`chinese.c:139`）。

### ② BG-10 —— ASCII 垃圾词过滤收紧（`9516b52`，`src/article_reader.c` +8/−2）

原判据 `wl<2 || has_underscore || has_digit || (!has_vowel && wl<6) || (!has_lower && wl>=4)`
对「2~3 字母」**结构性无效**（`BJE` / `RTO` / `IG` / `GPI` 含元音 ⇒ 两个条件都不触发）
⇒ 每次跑混进 **18~23 个碎片节点**。

新口径：`wl<3 || has_underscore || has_digit || !has_vowel || !has_lower`
（长度 ≥3 + 含元音 + 含小写）。回放登记里五组实测碎片：**18/18 + 23/23 全拦**。
代价（有意取舍）：`AI` / `OK` / `US` / `NASA` 这类全大写短词一并被拒。
残余：`CIWa` 这类「≥3 字母 + 大小写混杂」拦不住（只有查词表可以）⇒ 已登记、不做。
