## 零、缘起：079 只立了真值源，没碰数据结构

079 做完「语种口径收敛」后，在诚实边界里留了三条待决策项（D1 英文语料、D2 跨语种语义层、D3 状态格式 9→10）。其中 **D3** 记的是：

> `ReasoningNode` **没有 `lang` 字段**；12 个 `TopologyType` 全是功能维度、无语言维度；
> 中文词与英文词混在同一张词汇拓扑里。要真正「分语种」，迟早要给节点打 `lang` 标或分表
> —— 那是一次**状态格式升级**，必须单独一版、带迁移脚本。

老大拍板「**落**」：**本版就做 D3**，但只做「给节点打 `lang` 标」这一半 ——
**不做分表**，也不动跨语种边（D2 仍属专项轮）。理由：先让每个节点带上稳定的语种属性，
下游（扩散过滤 / 统计 / 将来的分语种分表）才有地基。

## 一、设计：`lang` 是 SSOT 的**物化缓存**，不是第二个真值源

本版最关键的一条约束：**落了盘，也绝不产生第二个「语种是什么」的答案。**

```c
/* include/huarong_topology.h — ReasoningNode 尾部新增 */
uint8_t lang;   /* PmLang 0..5：0=unknown 1=zh 2=en 3=ja 4=ko 5=other */
```

| 角色 | 是谁 |
|------|------|
| **权威（唯一真值源）** | `pm_lang_of(concept)` —— 079 立的那份 SSOT |
| **落盘字段** | `node->lang` —— **只是物化缓存**：把 SSOT 的结果算一次、存下来，供下游**免解码直读** |
| **加载期** | **无条件**按 `pm_lang_of(concept)` 重算并覆盖 |

也就是说：**文件里那个字节读回来对不对，最终都不决定内存里的值** —— 内存值永远由 SSOT 说了算。
落盘值的作用有二：① 下游子系统不必每次解码；② 作为一个**凭证**，加载时与 SSOT 比对，
不符就**纠偏 + 记账**（口径变更或脏数据的观测信号）。

写端定标点只有一处：`create_reasoning_node()` 在 `concept` 落定后写入
`node->lang = (uint8_t)pm_lang_of(concept)`。`concept` 创建后不再变 ⇒ 该值恒定。

## 二、写端：两条路径**必须同布局**

状态保存有两条路径，`lang` 字节**都要写、且位置完全一致**（否则同一份状态会因开关写出两种文件）：

| 路径 | 函数 | 触发 |
|------|------|------|
| **流式批（默认）** | `master_serialize_batch()` | 正常存盘 |
| **锁内（逃生门）** | `master_save_state_locked()` | `PIVOTMIND_SAVE=locked` 强制 |

两处均在每节点记录尾部、**紧接 `dist_sig_count`（int）之后**追加：

```c
fwrite(&ns->lang, sizeof(uint8_t), 1, fp);   /* [v10] 语种标签（1 字节） */
```

`SaveNodeSnap` 同步加 `uint8_t lang`，并在 capture 时从节点深拷贝。

> 注：状态文件是**顺序二进制流**（逐字段 `fwrite`/`fread`），不是定长记录 ——
> 因此**末尾追加字段天然向后兼容**：老二进制读到 `dist_sig_count` 就认为该节点结束，
> 不会越界；新二进制遇到老文件则按 `fmt_ver` 分支处理（见下节）。

## 三、读端：SSOT 权威 + 前向兼容（v2..v9 零迁移）

加载分 Pass 1（创建节点）/ Pass 2（恢复边）两遍（v0.5.22 的既有设计）。`lang` 段处理：

| `fmt_ver` | 文件里有没有 lang 字节 | 读端行为 |
|-----------|----------------------|---------|
| **`>=10`** | 有 | **读**该字节 → 与 `pm_lang_of(concept)` 比对；不符则 `lang_mismatch++`；**值一律以 SSOT 为准** |
| **`<10`（v2..v9）** | 无 | **不读**，直接由 `concept` 现算 ⇒ **前向兼容、零迁移脚本** |

- Pass 2 只恢复边，对 `fmt_ver>=10` 的文件**跳过** 1 字节 `lang` 段（已在 Pass 1 应用）。
- 收尾：`lang_mismatch>0` ⇒ `LOG_WARNING` 记账（`已按 SSOT 纠偏，口径变更或脏数据，非致命`）；
  否则 `fprintf(stderr, "lang 一致性: 全部节点与语种 SSOT 一致")`。
- **版本闸门未变**：`fmt_ver > STATE_FORMAT_VERSION` 仍**显式拒绝**并记账 ——
  故 `STATE_FORMAT_VERSION` 一旦升到 10，**只认 ≤9 的旧二进制会明确报错，而非静默误读**。

### ⚠️ 回退不可逆

一旦用 v0.5.36 存盘（`fmt_ver=10`），**退回只认 ≤9 的旧二进制会被闸门显式拒绝**。
线上换版前**必须备份 v9 状态文件**；本条已写进 `src/multi_topology.c` 的版本注释块。

## 四、契约单测（第 29 支）：为什么「存盘 → 读回 → 断言」证明不了持久化

新增 `tests/unit/test_lang_persist_unit.c`（**6 组 / 6 通过**：T0–T5）。

**动笔时最先撞上的是方法论问题**：加载端是 `huarong_net_add_node()` **重建**节点，
而 `create_reasoning_node()` 会按 SSOT 给 `lang` 定标 —— 所以**即使落盘那段字节完全没写、
甚至被当垃圾跳过，读回来的 `lang` 也照样「正确」**。

> **纯往返断言证明不了持久化存在。** 它只能证「加载后值对」，而那与「有没有落盘」无关。

故本单测改用**三个能真正变红的探针**，直接验**文件字节**而非内存对象：

| 组 | 手段 | 为什么能变红 |
|----|------|-------------|
| **T1** 文件字节探针 | 把每节点 `dist_sig_count` 写成**唯一哨兵**（`0x7A5A0000+i`），在文件里定位该记录尾部，直接看**紧随其后的那 1 字节** == 期望 `lang`；并断言头字段 `fmt_ver==10` | 若写端漏写该字节 ⇒ 哨兵后面紧邻的是下一节点的数据，探针必红 |
| **T3** 故意写脏 | 把某节点的 `lang` 字节改成错值（`PM_LANG_OTHER`），加载后要求：① 内存值**仍是 SSOT**、② stderr 出现「**lang 一致性: 1 个节点**」 | 那句话**只有在「字节确实被读到且不等」时才打印** ⇒ 反证「读端真的在读」 |
| **T4** 抽掉字节 | 按哨兵位置**删掉**每节点的 `lang` 字节 + 把头字段 `fmt_ver` 改回 `9`，加载后要求仍然全部对齐、值正确 | 证 `fmt_ver<10` 分支（旧文件零迁移）真的成立 |

另有 **T2** 往返（加载后节点数不变、每节点 `lang == pm_lang_of(concept)`，作为基础护栏）、
**T5** 双路径一致性（`fork` 子进程置 `PIVOTMIND_SAVE=locked` 存盘，
要求与流式批路径**文件逐字节一致** + `lang` 字节取值正确）。

**Makefile 7 处接入**（第 1 处同时修 079 的遗漏，见下节）：

`ASAN_TEST_TARGETS`（补 `test-lang-unit` + `test-lang-persist-unit`）/ `ASAN_TEST_BINS` /
编译规则 / 别名 `test-lang-persist-unit`（**第 29 支**）/ `TEST_BINS` / `test:` 前置依赖 / `.PHONY`。

夹具覆盖全部 6 个 `PmLang` 取值（中文 / 英文 / 日文 / 韩文 / 希腊西里尔 / 数字），
用 UTF-8 转义字面量书写，避免源码编码漂移。

## 五、顺带修复：v0.5.35 `make asan-test` 的「双清单」遗漏

写 Makefile 补丁时发现 079 留下的一个**潜伏 bug**：

> `make asan-test` 有**两张表** —— `ASAN_TEST_TARGETS`（构建）与 `ASAN_TEST_BINS`（执行）。
> v0.5.35 只把 `test_lang_unit` 加进了 `ASAN_TEST_BINS`，**没加进 `ASAN_TEST_TARGETS`**。
> 于是 `asan-test` 先 `make clean`、再只构建 TARGETS 清单，**随后却去执行 BINS 里那个
> 根本没被构建的二进制** ⇒ `[ -x ]` 不成立、**恒定 FAIL**。

v0.5.35 收尾时没跑过 `asan-test`，所以没人发现。**本版一并修正**：新增单测必须**同时**登记两张表，
本次 `test_lang_unit` 与 `test_lang_persist_unit` 两张表都有。（教训已写进 release 技能。）

## 六、诚实边界

- **本版只做「打标」，不做「分离」。** 12 个 `TopologyType` 仍是功能维度；
  中英词仍混在同一张词汇拓扑里 —— **分表 / 跨语种边（D2）不在本版**。
- **落盘 `lang` 不改变任何现有行为**：加载期一律被 SSOT 覆盖，下游暂无消费方。
  它是**为将来铺路的结构属性**，不承诺「本版就能分语种输出」。
- **未做迁移脚本**：靠顺序流「末尾追加」实现兼容，旧文件（v2..v9）零改动即可加载；
  但**新文件回退不可逆**（旧二进制显式拒绝）—— 线上换版前必须备份 v9。
- **`state_dump` 的语种分布节（079 立）仍按 `pm_lang_of` 实时统计**，本版**未改成读 `node->lang`**
  —— 保持「统计口径 = SSOT」，避免与物化缓存相互印证造成假象。
