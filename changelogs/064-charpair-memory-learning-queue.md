# 0.5.9 — 字符对记忆化与学习队列化

> **日期**: 2026-08-07 | **类型**: 架构 + 功能 + 性能

## 概述

从 0.5.8 的"结构稳得住"到 0.5.9 的"一切统计都是记忆"：字符对/字符表从"永久记账本"升格为**带生命周期的记忆痕迹**（权重/巩固度/活跃度/短期长期层级），遗忘≠删除（只降权不抹除）；/learn 从"每请求一线程"改为**固定 worker 队列**（线程 35→6）；POS 池降规模提速；探索记录与路径频率表同步修正生命周期哲学。

## 背景

0.5.8 修复锁纪律后暴露深层问题：
- **字符对表无限膨胀**：pair_count 185 万、2M 槽负载 91%、查找变慢、内存 64MB 常驻
- 早期方案被用户否决：截断=治标（问题推迟）；按"最近出现"遗忘="你好"几天不露面就被删（学了个寂寞）
- **用户拍板方向**：字符对 = 记忆痕迹，与字节点/边同构（权重/激活值/效价/巩固度），走记忆系统生命周期，冷冻与记忆结合
- **哲学定调**：遗忘≠删除（只降权，痕迹永在，再出现即回弹）；无限制器（负载由结构自消化）；冷启动安全（新生记忆不被误杀）

## 核心变更

### Added

- **字符对/字符表记忆化**（`article_reader.c`）：
  - `PairEntry`/`CharEntry` 新增字段：`consolidated`（巩固度 0~1）、`last_seen`（最近出现记忆 tick）、`tier`（短期/长期）——激活值不存储，由 last_seen 推导（省字段且天然衰减）
  - **Hebbian 巩固**：每次出现 `consolidated += 0.02 × (1-c)`（渐近线 1），≥0.5 晋升长期（tier=LONG，永不删除）
  - **表满清理**（唯一删除路径）：只清「未巩固 + 长期不活跃（>5 万记忆 tick）」的短期对；长期对永不删；用**重建式删除**（开放寻址表直接置空会断裂探测链导致条目丢失）
  - **冷启动安全**：新对 last_seen 新鲜 → 清理零误杀；表不满不触发
  - 记忆时钟 `mem_tick`（每处理一行 +1）作为时间源
- **学习队列化**（`pivotmind_gateway.c`）：
  - `/learn` 不再每请求 spawn detached 线程——固定 **2 个 worker + 256 容量环形队列**（满丢最旧，工作记忆丢弃策略）
  - 线程数 **35 → 6**（40 次采样全 6）
- **POS 池降规模**（`emergent_pos.h/.c`）：池上限 256→64（聚类 64² 相似度矩阵，单次快 16 倍）
- **探索记录生命周期**（`self_learner.c`）：覆盖策略从环形指针（插入序）改为「**悬垂优先回收**（节点已冻结/删除的记录）+ 最久未探索覆盖」——保留活跃探索记录
- **路径频率表淘汰修正**（`path_encoding.c`）：淘汰条件从"count 优先"改为「**低频 + 长期不活跃**」双条件——旧逻辑会误杀刚学的新路径（count=1 但新鲜）；表满且全活跃时不驱逐（新路径暂缓，等旧路径变冷）

### Changed

- **字符对表哲学**：从"记账本"（无限膨胀、无生命周期）→"突触"（形成→巩固→降权→不删除）——与 Hebbian 边权、冻结机制、三重记忆统一哲学
- **/learn 并发模型**：每请求一线程 → 队列 + 固定 worker（与感知 worker 同构——玄枢外部学习入口统一队列化）

## 验证

- **线程稳定**：12:09-12:29 全程 40 次采样线程全 6（修复前 35 稳态，雪崩时 274）
- **主循环健康**：ticks 正常（1s/tick），喂料期间无 STUCK
- **喂料推进**：节点 85046→92063，字符对记忆化不破坏词发现
- **POS 涌现**：额外词类 5 个已持久化（0→1→5）
- **冷启动安全**：重启后新对正常积累（无清理误杀日志）

## 已知问题

- **效价字段**（valence）已规划但未实现——情感种子/反馈传播统计留待后续（v0.6 候选）
- **激活值由 last_seen 推导**：查询时需计算衰减，暂未接入生成端（字符对激活目前只用于清理决策）
- **字符表 16K 槽固定**：汉字 2 万+ 可能满（当前 1584 字符远未到）；记忆化字段已就绪，表满清理逻辑待字符表逼近上限时补
- **pivotmind_state.dat 误跟踪**：180MB 运行数据在 git 历史中（已 assume-unchanged 忽略变化，彻底移除留待后续清理）
