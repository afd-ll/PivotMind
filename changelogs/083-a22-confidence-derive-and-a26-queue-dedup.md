## 二、接线：感知区的三路驱动

### 2.1 病灶

`perception_tick()` 把**上游三路信号全扔了**：

| 维度 | 上游本来就有 | 感知区实际做法 |
|---|---|---|
| 闸门 | 丘脑 `throttle[THAL_PERCEPTION]`（按全局状态在 0.0–0.7 分配） | 首行 `(void)throttle;`，注释写「纯随机模式不再需要 throttle 抽签」 |
| 动机 | 下丘脑 `drive_curiosity`（需求四驱力之一） | 未接 |
| 目标 | 海马体点单（走**直调** `perception_consolidate_node()`） | 自定「每 300 拍随机挑一词」的闹钟 |

⇒ 感知区成了一个**自己给自己派活、还不看红绿灯**的部门。

### 2.2 改法

1. **闸门**：拆除 `(void)throttle;`，改为 `if (!(throttle > PERCEPT_THROTTLE_MIN)) return 0;`
   —— 口径对齐 `visual_cortex_tick()`；写成 `!(x > MIN)` 是为了对 NaN 安全。
2. **动机**：节律改由下丘脑 `drive_curiosity` 调制（`hypothalamus_get_drive()` 此前**全仓零调用**）
   —— 基线 0.5 ⇒ 倍率 1.0；好奇心高 ⇒ 周期变短（问得勤），低 ⇒ 拉长；上下限 `[0.25, 2.0]`
   防止极端值把周期压到 0 或拖过长。
3. **目标**：候选词改由**三维度知识缺口**提供（`_gap_dialog_queries` / `_gap_template_queries` /
   `_gap_topology_queries`，三者此前**只有定义、零调用**），按 `cfg.gap_weights` 配额分配
   （最大余数法，保证配额之和 == max）+ 环形游标 `gap_cursor` 逐轮前移。
   **没有缺口就本轮不搜** —— 感知区不该自己给自己派活。
4. 顺手修 `is_valid_query()` 的恒假 bug（见 §四）。

## 三、A22：`confidence` 由「存量字段」改为「派生量」

### 3.1 病灶（探针实测）

三条缺口判据**全部要求「低置信度」**，而节点置信度曾是**只升不降**的存量字段：

- 节点置信度 **3894 样本 min = max = avg = 0.5000**（不是「聚在中档」，是**精确常量**）
- 边置信度 **33433 条亦精确 = 0.5000**；而**边权重是活的**（0.35–0.99 有分布）
- `batch_self_verify` 模拟：**升 2375 / 降 0 / 不动 0** ⇒ 伪双向
- 度分布：deg0 **1519** / 1-4 1099 / 5-9 453 / 10-19 392 / 20-49 282 / 50+ 149

⇒ 三维度缺口在真实数据上**结构性永不命中** —— 感知区即使接线完成，也一个字都搜不出来。

**旁证（第二处恒假 bug）**：`include/perception.h` 的 `int min_confidence_for_search`
接收 `0.1f` ⇒ **截断为 0** ⇒ `< 0` 恒假。

### 3.2 改法

`confidence` 改为**派生量**：证据 = **Σ 出边 `weight`**（唯一活量），按观测频率**分档**
（口径抄 `template_builder.c`），无出边落最低档 0.05；**不落盘**。四点接线：

1. `master_load_state` 收尾建基准
2. `dialog_system.c` 推理收尾重估，且**必须先于** `master_consolidate_confidence`
3. 头文件登记「**不落盘**」
4. `include/perception.h` 的 `int` → `float`

⚠️ **为什么不「接上 self_verify」**：`edge_conf_to_support(0.5f)` 落 `>0.3` 档返回 `0.5f`
⇒ `consistency ≡ 0.5` ⇒ 原样接上**只会把全库推到 0.95**，缺口判据**更不可达**。

### 3.3 实测改前 → 改后

| 指标 | 改前 | 改后 |
|---|---|---|
| 节点置信度 min / max / avg | 0.5000 / 0.5000 / 0.5000 | **0.050 / 0.900 / 0.368** |
| 维度2 模板缺口 | 0 | **2128** |
| 维度3 拓扑缺口 | 0 | **1519**（= 线上 deg0 孤岛数，自洽） |
| 推理评分乘子 | 恒 0.65 | **0.558** |

**端到端**：`perception_tick` 改前恒返 0 → 改后**首次出词第 100 拍**；
`throttle=0.05` 仍返 0（**刹车线有效**）、`curiosity=0.15` 推迟到第 200 拍（**驱力方向正确**）。

## 四、A26：缺口判据重复点单同一个词

### 4.1 病灶（读码确证，非推测）

三条判据取的是**同一个 vocab 子拓扑 + 同一个 `start`**、扫描顺序完全相同，且判据区间**包含**
（对话缺口 `confidence < 0.25` ⊂ 模板缺口 `confidence < 0.4`）；而 `_perception_enqueue()`
**只入队、不写 cache** ⇒ 同一轮内三条全通过 ⇒ **同一节点被重复入队**。

实测：`tick 200/250/300/350/400` 每轮入队 **2 个词且是同一个词**（`关羽 关羽`）；400 拍 6 轮共 **11 词**。

### 4.2 改法

入队前先做「**`is_valid_query` 过滤 + `strcmp` 去重**」原地压缩 `candidates[]`，再逐条入队。
**刻意不动**三条判据、配额与游标语义（`gap_cursor` 仍按原始 `got` 前移）。

### 4.3 行为 A/B（同一份线上状态只读快照）

| 指标 | 改前 | 改后 |
|---|---|---|
| 每轮入队 | 2 个（同一个词） | **1 个** |
| 400 拍累计入队 | **11** | **6** |
| 出词轮次 / 首次出词 | 6 / 第 100 拍 | 6 / 第 100 拍（**不变**） |
| 闸门 / 动机行为 | — | **不变** |

`11 = 1 + 2×5`、`6 = 1 + 1×5` ⇒ 差额恰好是 5 个重复项 ⇒ **只去掉重复，判据零变化**。

## 七、诚实边界

- **A22 改动了 `confidence` 的语义**：它同时被 `multi_topology.c` 的推理评分乘子消费
  （`score *= 0.3 + 0.7*conf`）⇒ **推理排序会变**（乘子恒 `0.65` → `0.558` 是实测值）。
  本版**只验证了「缺口判据复活」与「端到端能出词」**，**未做输出质量的 A/B** ——
  「能出词」不等于「出得对」。这一层留给后续。
- A26 只去掉重复入队，**没有改判据**，因此**不解决**「三条判据扫描顺序完全相同」
  （同起点、同方向 ⇒ 配额只决定「取几个」、不决定「从哪取」）这件事。
- `confidence` **不落盘**（每次由边证据现算）⇒ 加载旧状态后必须等一次重估才生效；
  已在 `master_load_state` 收尾做了一次。
