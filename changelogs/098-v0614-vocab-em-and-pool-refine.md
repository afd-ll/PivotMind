## 一、这一版是什么

一句话：**把「什么算一个词」从逐候选投票换成全局最优化；把「输出哪几个词」从按分数硬凑换成复用输入的语序。**

两条主线，依赖顺序是「先词表、再生成」：

1. **词表**（CX-45）：`qa_retrain` 阶段二的晋升判据，从 `PMI + 左右熵` 换成**离线 EM 词表白名单**；再补「成分独立率」与三字词。
2. **生成端**（CX-32 / CX-48 / CX-50）：先拆掉 QA 记忆对生成层的截流（否则一切生成改动都测不出来），再修候选池的两个结构性问题——同族词占满 4 个槽、跨边界组合抢走正确切分。

外加**一条安全修复**（CX-46：语义自清洗默认关）与**四条证伪记录**（见第五节，写下来是为了不再重走）。

## 二、词表判据换轨（CX-45）

### 2.1 为什么换

原判据是逐候选独立投票：`PMI≥2.5` / `min熵≥2.0` / `次数≥20`。三关叠加的结果是**既滥又漏**——
`公吵`（「老公吵架」的切片）能全过，而 `你好`、`乒乓球` 在整个状态文件里 grep 到 0 次。
问题是结构性的：任何单点阈值都有误杀面和漏收面。

### 2.2 换成了什么

新增 `tools/unigram_lm.py`：Unigram LM + EM（Viterbi 期望计数 + 剪枝 + 词表规模扫描 + 长度代价 λ）。
目标函数从「每个候选各自过关」变成「整个语料切出来的总似然最大」。

三步落地：

| 步 | commit | 做法 |
|---|---|---|
| ① EM 白名单 | `f9cddfc` | 阶段二不再跑 PMI 与词整体熵，命中 `data/word_lm_vocab.tsv` 即晋升 |
| ② 成分独立率 | `9d5c11d` | 加 `--indep-pmi 2.5`：按切分后的 `PMI = log[P(ab)/(P(a)P(b))]` 剪虚词粘连 |
| ③ 三字词 | `15dbe62` | 词长从固定 2 放开到 2~3，配**三重闸门** |

**① 的取舍**：白名单只替代「闸门」，不替代「测量」。`word_ctx.bin`（词整体实测熵）仍按语料回扫产出，
否则 `--prob` 与后续判据全部断粮。第一版误砍过它，跑出 0 条才发现。

**③ 的三重闸门必须一起上**（实测任何单一统计量都漏一边）：

- `MI≥4.5`（对最优二分切分）压虚词粘连：`是一个` 3.63 / `自己的` 3.69
- `min熵≥1.0`（词整体左右邻）压切偏块：`工智能` 0.00 / `文回答` 0.01
- 虚词守卫（首/尾是封闭类虚词字、剩余部分是词 ⇒ 拒）补撞车盲区：`有一个` 4.48 与真词 `大学生` 4.48 同分

### 2.3 结果

| 项 | 旧判据 | EM 白名单 |
|---|---|---|
| 晋升词数 | 29,480 | 29,173 |
| 节点 / 边 | 35,604 / 129.15 万 | 35,236 / 129.03 万 |
| 阶段二耗时 | 数分钟（全语料回扫 + 熵闸） | **82 秒** |

三字词上线后：**31,853 节点**（6,063 单字 + 24,813 双字 + 924 三字），边 127.7 万。

held-out `logP/char`（全量 3,477.6 万汉字）：旧表 17,400 词 **−5.1294**；EM(max_len=2) 70,267 词 **−4.7497（+7.4%）**，同规模（2 万词）**+5.7%**。

### 2.4 一条推翻自己的结论

原以为「碎片拿不到概率质量，会自然死」——**只对一半**。
低频切片确实掉长尾（`用太` 第 69,791 名），但高频跨边界二元组根本没死：`性和` 排第 **654**（真词 `你好` 是 565）、`的原` 第 12,051。
原因很硬：拆成 `性`+`和` 要多付一次 `P(和)=0.016`（全表第二高），合成一个 token 似然更高。

⇒ **总似然是「分词质量」的尺子，不是「词表纯度」的尺子。** 它能替代阈值调参，替代不了词感判断。

## 三、生成端（CX-32 / CX-48 / CX-50）

### 3.1 先拆截流（CX-32）

原判据：`score = match / sqrt(词条长度+1)`，且 **`match > 0` 即命中**。按字分词 + 一个字就命中
⇒ 任何输入都能撞上一条 QA，占掉 `response` 槽位，**生成层从不被调用**（实测 8/8 全被截流）。

改成 Dice 系数 + 优先级重排：**≥0.95（近逐字重复）才直接回**，其余交给生成层；生成交白卷时用 0.30 宽松兜底。

为什么不靠调阈值：按字重合分不开语义——`盐是什么味道` vs `屎是什么味道` 0.833、`你会用计算机吗` vs `你是计算机吗` 0.769、`今天天气怎么样` vs `今天运气怎么样` 0.923。

**分词器未改动一个字**（`src/utf8_tokenizer.c` 零 diff），仍按字切。

结果：8 条输入走 QA 从 8/8 降到 **3/8**，5 条走生成层。

### 3.2 候选池精修（CX-48）

DUMP 实测的病象：候选池按分数排好序，但**同一字族连续占满 4 个输出槽**：

```
我想学习编程 → 学习编程(锚定) 学习 我想 编程 || 想学 想想 想吃 苹果 什么 …
他喜欢听音乐 → 喜欢 音乐 欢乐 欢喜 || 喜欢吃 惊喜 喜剧 乐器 快乐 喜悦 …
```

输出因此是「学习的编程的我想编程」。三条规则：

1. **同族收敛**：与已留项共享任一汉字即剔除。判据用**词形不是语义指纹**——
   `word_embed.bin` 只覆盖 7,061 词（`WEMB_MIN_NNZ=3` 过滤后），实测 12 个待判词里只有 1 个有指纹，
   `wemb_similar` 对缺失词恒返 −1.000。
2. **相对分数下限 0.25×peak**：相关候选在 0.5~1.0，跑题词在 0.10~0.20
   （`我想学习编程` 里的 `苹果` 0.196、`我想吃苹果` 里的 `编程` 0.169）。
   **三档先严后宽保底**：池子 <2 会掉进字级联想兜底，实测输出 19 个单字串。
3. **排序键 `[命中输入, 输入内出现位置, 长度, 分数, 原序]`**：用户输入本身就是合法中文语序，
   命中词按原位置排 = 直接复用他的话序。

配套两处：

- **连接符注入**：两词都命中输入且同序 ⇒ 不插。原来「我想」+「学习编程」被插成「我想和学习编程」。
- **bigram 打分重排默认关**（`PIVOTMIND_TM_ORDER=1` 才开）：它把「喜欢/听音乐」排成「听音乐/喜欢」，反而破坏输入语序。

### 3.3 重叠裁决（CX-50）

CX-48 之后剩下的两条错全部指向词表切片词：`我最近很累 → 我最很累`（`我最` 是「我最近」的前缀）、`我想找份工作 → 我想份工`。

判据：**同族 + 位置重叠 + 唯一冲突 ⇒ 比「词整体左右邻 min 熵」，高者留。**
实测 `我最` 0.727 < `最近` 1.640、`份工` 0.104 < `工作` 5.087、`很好` 1.94 < `好看` 3.21。

三条防误杀（缺一不可）：

1. **只对重叠候选生效** ⇒ `因为`(2.66) / `时候`(2.07) 这类不重叠的真词完全不受影响。这是它比全表判据强的根本原因：**不做全表判定，只做局部裁决**。
2. **只对 2 汉字词生效** ⇒ 三字词的熵恒 0（`word_ctx` 硬编码二元组，CX-47），不豁免的话 `计算机` 会被当成最差的词。
3. **冲突 >1 禁止顶替** ⇒ `想学` 既是 `我想` 的重叠对手、又与 `学习编程` 共享「学」，允许它顶替会连锁砍掉两者。

### 3.5 一个必须记下的代价

同一批 20 条的**回声检查**：走生成路径的 14 条里，**13 条回复是输入的子序列**（93%），平均长度是输入的 78%。

也就是说：**干净了，但更像「原句抽实词」，不是「生成」。** 这是本版最需要正视的一条——
指标（重复率、覆盖率）改善是真实的，但它度量的是「不重复、像人话」，不是「答得好」。

## 四、安全修复（CX-46）

`brainstem_prune_nonwords()`（语义自清洗）**默认翻转为关**，`PIVOTMIND_NONWORD_PRUNE=1` 才启用。

原因：`min熵≥2.0` 判据方向反了——低熵是高品词的位置效应（`因为` 左熵 1.05、`再见` 右熵 1.49），
不是非词证据。全量实测：存活词 n≥1000 且 min熵<2.0 有 **184 个**（`因为` 29,609 / `时候` / `机器` 18,040 / `告诉` / `其中` / `你说`），
n≥20 合计 **3,882 个**；activation 随运行衰减跌破 0.01 后会批量误杀核心词。

顺带 `58fe13d`：`vocab_coverage --dump` 导出全量词表（词名/边数/冻结/激活）。

## 五、证伪记录（写下来是为了不再重走）

这一节比上面的功能更值钱：五条路都试过，都定量否决了。

### 5.1 bigram 走边生成 —— 到顶了

转移表按当前词表重建：218 万唯一对（26MB）。但**分布天生平**：`学习` 有 **77,428** 个后继、top-8 熵 **0.00**，
走一步等于在七万多个词里抽签。剪枝救不了（砍掉的是 80%+ 概率质量）。

试过只吃答案侧（34,444 后继）、只吃小黄鸡答案侧（685 后继 / 熵 0.39，分布终于可用但只有 23.9 万对、
覆盖太薄 ⇒ 重排 0 次触发）。

最终降级为**候选组合打分器**（`8509c07`）：不做生成，只排序；两词允许一跳桥接 `A→x→B`（x 取 A 的 top-24 后继，桥接扣 1 nat）；
顺序用子集 DP 求最大分汉密尔顿路（n≤10）。技术有效（可评分对从 0 提到 14），**但输出没改善**——因为被排序的词本身就是近义词堆。

### 5.2 `relevance` 恒 1.000 —— 该问题不需要修（CX-49）

DUMP 里连 `收/原/找/作/表/解` 的 `rel` 都是 1.000。四种口径全试过：

| 口径 | 学习（相关） | 苹果（跑题） | 区分度 |
|---|---|---|---|
| wmax（现 relevance） | 1.000 | 1.000 | 无 |
| 按锚定归一 wnorm | 1.000 | 1.000 | 无 |
| 锚定个数 wcnt | 9 | **10** | 反向 |
| 权重和 wsum | 8.60 | 7.22 | 1.4× |
| 对照 `vocab_score` | 6.18 | 0.82 | **7.5×** |

根因：图里边权普遍打满（`QA_W_FWD`/`QA_MAX_FWD` 上限），「有满权边」只代表有边，不代表语义相关。
**不是公式问题，是数据没这个信息。** 相关性实际由 `vocab_score` 承担。

⚠️ **但它不可中性化**：仍区分「跳数」（满权一跳乘子 2.0 / 两跳约 0.6）。设成 1.0 后输出立刻变差
（`我想学习编程` 多出 `苹果`），已回滚。诊断口：`PIVOTMIND_REL_DIAG=1`。

### 5.3 切片词的词表级判据 —— 三条全废

| 判据 | 结果 |
|---|---|
| EM 全局似然「反修词表」 | ❌ `我最` 在 Viterbi 里**真会被选中**（`我最/喜欢` 比 `我/最/喜欢` 少切一刀）|
| 封闭类成分 + 双向替换自由度 | ❌ `可是`(38/52)、`因为`(40/13)、`所以`(14/40) 与 `我最`(10/79) 同型，误杀 7 个真词 |
| MI≥2.5 / min熵 | ❌ `份工` PMI **7.76**、`却很` min熵 **5.077**（比真词 `天气` 4.941 还高）、`我最` 次数 50,387 |

结论：这类「低频虚词 + 常用字」组合在统计上与真词不可分。**只能靠用法（重叠裁决）而非判词。**

### 5.4 LCCC 对话语料 —— 三项用途全不成立（CX-51）

找到免费源（`silver/lccc`，MIT，580MB / 473 万轮，含微博/字幕/贴吧/豆瓣；`hf-mirror` 可下，`huggingface.co` 直连不通）。

## 六、已知问题（本版未修）

1. **CX-52 `activation` 无界增长**：线上 state 里 `P50=0.30` 但 **P90=3.85e10 / P99=1.36e17 / max=8.9e22**，且被存盘。
   `*= boost`（`diffusion.c:1988`，boost∈[0.5,1.5]）与 `+= strength`（`diffusion.c:1138`）两条路径都没有 clamp，

4. **`word_ctx` 硬编码二元组**（CX-47）：三字词测不了左右邻熵，只能用 EM 期望计数代门控。
