# 审查报告 011-A — 语义拓扑跨拓扑投票接入

> 配对修复报告：011-B
> 日期：2026-05-27
> 来源：[架构改进方案_语义+因果.md](../docs/架构改进方案_语义+因果.md)

## 一、审查目标

`topology_walk_greedy()` 的路径回溯（第8维评分）只在词汇拓扑内部查边，不参考语义拓扑的连接。接入语义拓扑作为额外投票源。

## 二、现状分析

### 2.1 当前代码（L1305-1325）

```c
float path_context_score = 0.0f;
int path_ctx_count = 0;
for (int pi = 0; pi < path_len; pi++) {
    int pid = path_out[pi];
    if (pid < 0 || pid >= node_count || pid == current_id) continue;
    ReasoningNode* pn = net->nodes[pid];
    if (!pn) continue;
    for (int ej = 0; ej < pn->connection_count; ej++) {
        if (pn->connections[ej] == target) {
            path_context_score += pn->connection_weights[ej];
            break;
        }
    }
    path_ctx_count++;
}
float avg_path_weight = (path_ctx_count > 0) ? path_context_score / path_ctx_count : 0.0f;
float path_ctx_norm = avg_path_weight / 5.0f;
```

**问题：** 只查 `pn->connections`（本拓扑内边），不利用跨拓扑连接中的语义信息。

### 2.2 函数签名

```c
int topology_walk_greedy(SubTopology* sub, int start_node_id,
                         int* path_out, float* scores_out,
                         int max_len, unsigned char* visited,
                         float intent_weight);
```

仅有 `SubTopology*`，无法访问 `MasterTopology*`，因此无法遍历跨拓扑连接。

### 2.3 三个调用点都能获取 MasterTopology

| 文件:行号 | 上下文 |
|-----------|--------|
| `dialog_generate.c:111` | 有 `dsys->master` |
| `associative_reasoning.c:380` | 有 `engine->topology` |
| `multi_topology.c:1122` | 在 `master_generate_response()` 内有 `master` |

## 三、改动方案

### 3.1 签名修改

末尾增加 `MasterTopology* master` 参数。`NULL` 时退化为原行为。

### 3.2 路径回溯循环（L1305-1325）

增加语义拓扑跨拓扑投票段：遍历 `master->cross_links`，找路径节点 → `TOPO_SEMANTIC` 的跨拓扑连接，累加 `link->weight` 到 `semantic_cross_score`。

### 3.3 评分公式（L1329-1339）

```c
// 原：EDGE_WALK_W_PATH_CTX * path_ctx_norm;
// 改：分拓扑归一化后加权
EDGE_WALK_W_PATH_CTX * path_ctx_norm * 0.6f +
EDGE_WALK_W_PATH_CTX * semantic_cross_norm * 0.4f;
```

## 五、风险

1. **跨拓扑 O(n) 遍历**：cross_links ~12万条，候选节点多时可能慢（后续可改用 cross_adj）
2. **语义拓扑可能为空**：需判空，为空时 semantic_cross_score 保持 0
3. **边权尺度不同**：分拓扑归一化 /5.0f 是临时值，后续可能需要独立上限参数
4. **简化版不查 target 的反向映射**：仅利用路径节点的语义支撑，不做双向查询
