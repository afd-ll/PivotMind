## 一、审查目标

基于 012/013 全量修复后的架构讨论，识别"拓扑走边路线作为 LLM 竞品"的核心瓶颈，给出最小改动方案和后续路线。

## 二、关键发现

### P0：extract_unique_chars 去重毁灭字序

**位置**：`src/autonomic_learner.c:213-246`（旧函数）

```c
static int extract_unique_chars(const char* text, char chars[][8], ...) {
    // 对每个字符，检查是否已在 chars 数组中
    int already_exists = 0;
    for (int i = 0; i < count; i++) {
        if (strcmp(chars[i], buf) == 0) { already_exists = 1; break; }
    }
    if (!already_exists) { ... count++; }  // 重复字被丢弃
}
```

**后果**：
- "我爱你" → `{'我','爱','你'}`，"你爱我" → 同样 `{'我','爱','你'}` — 完全无法区分
- 已存在的位置衰减代码 `wmult = 1.5f/dist`（L395-396）作用在去重后的假序列上，dist 是数组索引差而非原始位置差
- 这是"训练 20 轮后仍是乱码"的根因之一

**修复**：改为 `extract_ordered_chars`（保序不去重），改动仅 1 个函数。节点复用由 `trace_wisdom_net_find_or_create_node` 保证，不重复创建。

---

### P1：topology_walk_beam 声明但未实现

**位置**：`include/multi_topology.h:299-305`

```c
int topology_walk_beam(SubTopology* sub, int start_node_id,
                       int* path_out, float* scores_out,
                       int max_len, unsigned char* visited,
                       float intent_weight);
```

声明完整但函数体从未实现。贪心走边 `topology_walk_greedy` 每步只看当前最优，无全局视野。

**设计**：Beam K=3，每步扩展所有候选 → 按累积得分保留 K 条 → 最终选全局最优。3 倍计算量换路径质量。

---

### P2：ReasoningNode.features 是冻结伪随机数

**位置**：`src/feature_io.c:201-207`

```c
int rbase = node->node_id * 31 + t * 997 + 12345;
node->features[j] = ((float)rv / 100000.0f) - 0.1f;  // 冻结，从未更新
```

全代码库中没有任何地方对 features 进行学习更新。但至少有 5 处余弦相似度计算依赖它：
- `dialog_system.c:113` — 激活传播
- `cross_edge_io.c:254` — 跨拓扑建边
- `active_learner.c:462` — 主动学习
- `multi_topology.c:534/1323/2005` — 走边 + 语义投票 + 最近邻

**后果**：所有"语义相似度"本质上是对 node_id 哈希值的余弦运算。这是整个架构中最根本的表示学习缺失。

**推荐方案**：GloVe 式加权最小二乘回归，直接消费 autonomic_learner 已有的共现统计，一次求解不需迭代训练。纯 C 实现（仅需 dgels 或手写共轭梯度）。

---

### P3：字序编码可进一步加强

已存在的位置衰减（`wmult = 1.5f/dist`）在 P0 修复后已能区分序列。可选增强：在 `ReasoningNode` 加 `int prev_in_seq` 或三元组位图，走边时对已存在的链式路径给额外奖励。
