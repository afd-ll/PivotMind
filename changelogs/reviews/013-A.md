## 二、发现问题

### P0-1：剪枝函数未被调用（死代码） 🔴

**位置**：
- `src/huarong_topology.c:441` — `huarong_net_prune_edges()`
- `src/multi_topology.c:386` — `master_prune_cross_links()`

**现状**：两个函数有定义、有声明、有注释，但全文搜索无任何调用点。属于死代码——拓扑边和跨拓扑连接持续增长的问题未被实际解决。

**修复**：在 `autonomic_request_flush()` 刷盘前调用：
```c
// 刷盘前先剪枝
huarong_net_prune_edges(vocab->net, 0.05f, 0.02f);  // 词汇拓扑
master_prune_cross_links(master, 0.05f, 2);
// 然后再 master_save_state()
```

**影响**：边数单调增长问题持续存在（README §已知局限 3），长期运行内存压力增大。

### P0-2：master_save_state 中 cross_links NULL 槽位未处理 🔴

**位置**：`src/multi_topology.c:2129-2145`

```c
int cross_link_count = master->cross_link_count;        // L2129
fwrite(&cross_link_count, sizeof(int), 1, fp);          // L2130

for (int i = 0; i < master->cross_link_count; i++) {    // L2133
    CrossTopologyLink* link = master->cross_links[i];
    if (!link) continue;                                // L2135 跳过 NULL
    ...
    saved_links++;
}
```

**问题**：头部写入的 `cross_link_count` 包含 NULL 槽位，但循环体跳过 NULL。加载时读到的 link 数量比声称的少，导致后续数据解析错位。

**场景**：`master_prune_cross_links` 将部分 link free 并设 NULL 后，下次 `master_save_state` 就会写出不一致的数据。

**修复**：在写入前统计实际非 NULL 的 link 数量，或保存时压缩数组（先 compact 再写）。

### P2：pruning.c 中 quickselect_float 未处理 right < left 的边界

**位置**：`src/pruning.c`（quickselect_float 函数）

```c
static void quickselect_float(float* arr, size_t k, size_t left, size_t right) {
    while (left < right) { ... }
}
```

当 `left >= right` 时直接返回，这是正确的。但当 `k > right` 时会死循环（虽然调用处保证 k < size，但防御性不足）。

**影响**：低。调用方都保证了 k < size，但加一个 assert 或边界检查更安全。
