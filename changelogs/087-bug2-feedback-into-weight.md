## 二、病灶回顾

`confidence` 在 v0.5.40（A22）改成**派生量**（= f(Σ 出边 weight)）之后：

```c
/* dialog_reason() 每轮都跑 */
batch_self_verify(master);                   /* 按边证据【覆盖写】confidence */
master_consolidate_confidence(master, 0.1f); /* 给"刚用过"的节点 confidence += 0.1 */
```

⇒ 那 `+0.1` **下一轮被 `batch_self_verify` 重新算掉** ⇒ **只活一轮**。
⇒ 机制从「**学习量累积**」退化为「**单轮临时偏置**」——「用得对就记住」**没有发生**。

## 三、修法：反馈写进它唯一的真值源

```c
/* src/multi_topology.c · master_consolidate_confidence() */
if (!node || node->activation <= 0.3f) continue;
if (!node->edges || node->edge_count <= 0) continue;

float share = boost_factor / (float)node->edge_count;   /* 均摊，总量与旧口径可比 */
for (int e = 0; e < node->edge_count; e++) {
    if (!node->edges[e].target) continue;
    node->edges[e].weight += share;
    if (node->edges[e].weight > 1.0f) node->edges[e].weight = 1.0f;
    boosted_count++;
}
```

**四条理由（按重要性）**：

1. **`weight` 才是"记忆"**：它**持久化**（落盘）⇒ 反馈从此跨会话存在。
2. **自洽**：`confidence = f(Σ weight)` ⇒ 下一轮重算时这份反馈**被自然算进去**
   ⇒ 机制**重新变成累积的**，且**不需要任何新字段 / 新格式**。
3. **合 SSOT**：没有引入「派生 + 存量」的混合体（那正是 A22 要消灭的东西）。
4. **语义自然**：这节点刚被用过且用得对 ⇒ **它跟邻居的连接更强**。

**为什么均摊而不是每条加满**：保证**总增量**与旧口径（给节点 +boost_factor）可比；
`share = boost_factor / edge_count` ⇒ 度越大、单边增量越小 —— 符合"证据越多、单条越不重要"的直觉。

## 五、诚实边界

1. **A/B 只证明"无副作用"，没证明"更好"**（见 §四）。
2. 🔴 **`weight` 只有加、没有减** ⇒ 长期"用得对"会让边权**单调上升直到钳位 1.0**。
   旧实现（改 `confidence`）本来也有同样问题，但 `confidence` **每轮重算会自动泄压**，
   **`weight` 不会** ⇒ **这是一条本版新引入的长期风险**，登记在册
   （要不要给 `weight` 加衰减，属独立决策）。
3. **线上仍未部署**（线上是 v0.5.34）。
4. **未做**：长跑回归 —— 本改动的对象是"跨轮累积"，而长跑护栏抓的是 **tick 级死锁**，
   **不对口**（不构成验证）；也未做 TSan 并发检测。
