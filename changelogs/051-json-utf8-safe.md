# 0.4.10 — JSON 响应 UTF-8 安全化 + 词汇拓扑深度清理

> **日期**: 2026-07-01 | **类型**: 修复

## 概述

解决 gateway `/chat` 回复中偶发 JSON 编码崩溃（`UnicodeDecodeError: invalid continuation byte`）问题。双管齐下：顶层 json_escape 加 UTF-8 校验跳过无效字节，底层用 clean_vocab 清理词汇拓扑中的搜索垃圾节点。

## 核心变更

### 1. json_escape UTF-8 安全化

**文件**: `demos/pivotmind_gateway.c` (第 138-154 行替换为新版)

新增两个辅助函数 + 重写 json_escape：

- `utf8_seq_len()` — 判断字节的 UTF-8 序列长度 (1/2/3/4, 0=无效)
- `utf8_valid()` — 校验完整多字节序列
- `json_escape()` 新增：
  - 控制字符 (0x00-0x1F) → `\uXXXX` 转义
  - 无效 UTF-8 字节 → 直接跳过，不写入输出
  - 有效多字节序列 → 原样复制

即使拓扑中存在损坏的节点概念，gateway 回复也不会再崩坏 JSON。

### 2. 词汇拓扑深度清理

**工具**: `tools/clean_vocab` — 删除 372 个搜索垃圾节点

| 类型 | 示例 | 数量 |
|------|------|------|
| 搜索 URL 编码碎片 | `-搜索//////\%E\%B` | ~150 |
| 中文-英文混合碎片 | `司Anthropic`, `涨0.7%` | ~60 |
| 非 UTF-8 字节 | `\x80搜索`, `%E%AA` | ~20 |
| 路径/标记垃圾 | `px-搜索////-搜索//` | ~100 |
| 整句污染 | `验证码`, `\x00\n//%E%AD` | ~40 |

状态文件: 15MB → 14MB，节点数: 7030 → 6658
